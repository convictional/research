## [LycheeCluster: Efficient Long-Context Inference with Structure-Aware Chunking and Hierarchical KV Indexing](https://arxiv.org/abs/2603.08453v1)

## Paper Summary

LycheeCluster introduces a novel KV cache management method for accelerating long-context LLM inference during the decoding phase. The core insight is that existing retrieval-based sparse attention methods fail because they fragment semantic units — fixed-size paging (Quest) arbitrarily cuts context at physical boundaries, while token-level clustering (ClusterKV) scatters locally coherent tokens across disjoint clusters. LycheeCluster addresses this with two key innovations: (1) **structure-aware chunking** that segments context into variable-length, semantically coherent chunks using a hierarchical delimiter system (paragraph breaks → sentence endings → phrasal punctuation → whitespace), and (2) **hierarchical KV indexing** that organizes chunks into a three-level tree (coarse units → fine clusters → chunks) enabling sub-linear retrieval via triangle inequality-based upper bound pruning.

During the prefill phase, the system builds the index by mean-pooling token keys within each chunk, then applying spherical k-means clustering to create fine clusters and coarse units. During decoding, each query traverses the tree top-down, pruning irrelevant branches using mathematically bounded attention score estimates. A lazy incremental update strategy handles streaming generation by buffering new tokens and grafting completed chunks onto the nearest existing cluster. The method achieves up to 3.6× decoding speedup over full attention with negligible performance degradation — and in some cases *outperforms* full attention by acting as a noise filter. The pilot study alone showed +15% accuracy on JSON extraction tasks simply by aligning retrieval units with semantic boundaries.

The paper validates across LongBench V2 (long-context understanding), MATH500 (complex reasoning), and RULER (retrieval/aggregation), demonstrating consistent improvements over Quest, ClusterKV, ShadowKV, and other baselines. Index overhead is ~1% of KV cache memory, and the lazy update mechanism consumes <1% of decoding time.

## Relevance to Decide

This paper is highly relevant to Decide's **AI Moat** goal, specifically the "premium on token spend" framing and the need for production-viable techniques that make Decide's token expenditure yield better outcomes than commodity spend. Several product areas would benefit:

**1. Research Pipeline (High Impact):** Decide's multi-iteration research pipeline (ResearchJob → ResearchIterationJob → ResearchQueryJob) synthesizes long contexts — up to 30K token budgets for final synthesis. Structure-aware chunking directly applies to how research results, learning extractions, and follow-up queries are organized in context windows. The hierarchical indexing concept could be adapted to manage the accumulated research context across iterations, ensuring that when the LLM generates synthesis, it attends to semantically complete research findings rather than arbitrarily truncated fragments.

**2. Meeting Intelligence (Medium-High Impact):** Meeting transcripts with WebVTT parsing, speaker attribution, and timestamps are inherently structured. The delimiter hierarchy (speaker changes, paragraph breaks, sentence endings) maps perfectly to LycheeCluster's structure-aware chunking. When generating summaries from long transcripts, preserving complete speaker turns and topic segments as atomic retrieval units would improve summary quality — particularly for long meetings that exceed context windows.

**3. Goal Alignment Scoring (Medium Impact):** The batch goal alignment job scores all content against active goals using vector pre-filter then LLM scoring. The paper's insight about semantic integrity in retrieval directly applies — when content is chunked for embedding and comparison, structure-aware boundaries would produce more meaningful similarity scores than arbitrary truncation. The hierarchical indexing concept could also optimize the vector pre-filter step.

**4. Hybrid Search (Medium Impact):** Decide's ContentSearch uses 70% vector + 30% BM25 with max 500 vector + 300 text candidates. The structure-aware chunking principle could improve how content is indexed — ensuring that Content embeddings represent semantically complete units rather than fixed-size fragments. This is particularly relevant for structured content like decision matrices, goal hierarchies, and email threads.

**5. Decision Intelligence (Medium Impact):** When generating options, criteria, and trade-off analysis, the LLM processes structured decision context (options with evaluations, criteria with ratings). The paper's demonstration of +15% improvement on JSON extraction by respecting structural boundaries is directly applicable to how Decide formats decision data in prompts.

**6. Email Integration (Lower but Notable):** Email grouping by goals and smart collections involve processing email threads — inherently structured content with clear delimiters (message boundaries, quoted text, signatures). Structure-aware chunking would improve how email content is prepared for LLM analysis.

## Implementation Approach

### Phase 1: Structure-Aware Prompt Chunking (Small Experiment, 1-2 weeks)

**What to build:**
- A `StructureAwareChunker` utility in `app/lib/` that implements the hierarchical delimiter system (Table 4 from the paper) for segmenting content before it enters prompts
- Integrate with the Jinja2 prompt engine in `app/prompts/` — when assembling long contexts (research synthesis, meeting transcripts, decision contexts), use structure-aware chunking instead of arbitrary truncation
- Implement min/max chunk size constraints (8-16 tokens at the KV level, but for prompt-level chunking, likely 50-200 tokens depending on content type)

**Data needed:**
- Existing meeting transcripts, research results, email threads, and decision contexts from production
- Ground truth or human evaluation of summary/analysis quality before and after

**Key challenges:**
- Decide uses Claude via Anthropic's API, not self-hosted models — we can't directly modify KV cache management. The applicable insight is at the **prompt construction** level: how we organize and chunk content before sending it to the LLM
- Need to map the delimiter hierarchy to Decide's content types: meetings (speaker turns, timestamps), emails (message boundaries), research (source boundaries, iteration boundaries), goals (hierarchy levels)

### Phase 2: Hierarchical Context Organization for Research Pipeline (Medium Feature, 2-4 weeks)

**What to build:**
- Modify `ResearchIterationJob` and the final synthesis step to organize accumulated research context hierarchically rather than as a flat concatenation
- Implement a lightweight version of the coarse→fine→chunk hierarchy for research context: group findings by topic cluster, then by source, then by individual finding
- Use the existing pgvector embeddings to cluster research findings before assembling the synthesis prompt, ensuring the most relevant clusters are prioritized within the 30K token budget

**Components to modify:**
- `app/prompts/` templates for research synthesis
- Research pipeline jobs to add a clustering/organization step before final synthesis
- Potentially the `ContentSearch` module to support structure-aware retrieval

## [One Model Is Enough: Native Retrieval Embeddings from LLM Agent Hidden States](https://arxiv.org/abs/2603.08429v1)

## Paper Summary

This paper addresses a specific redundancy in RAG pipelines: when an LLM agent generates a search query, it produces rich hidden states that encode the full conversational context, but these are discarded. A separate embedding model then re-encodes the generated query text from scratch. The authors propose attaching a lightweight ~25M parameter projection head (linear layer → 2-layer transformer encoder → mean pooling → output projection with L2 normalization) to the LLM that maps its hidden states directly into the embedding model's vector space, eliminating the need for the separate encoder at inference time.

The projection head is trained via knowledge distillation using three complementary losses: (1) alignment loss (cosine similarity to teacher embeddings), (2) contrastive InfoNCE loss (preserving discriminative structure across queries), and (3) rank distillation loss (KL divergence on document ranking distributions). Evaluated on the QReCC conversational search benchmark using Qwen3-8B as the LLM and Qwen3-Embedding-8B as the teacher, the method retains 95-97% of baseline retrieval quality while achieving a 21.8× latency reduction (43.5ms → 2.0ms per query) by eliminating the embedding model forward pass. Key findings include that alignment loss is the strongest individual component, rank distillation collapses without alignment anchoring, and extended training with lower learning rates provides the largest single improvement.

The paper is methodologically sound with 12 ablation configurations, bootstrap confidence intervals, and statistical significance testing, though it is limited to a single dataset and a same-family model setting (both models from Qwen3), which likely benefits from shared pretraining representations.

Every content indexing and search operation requires a separate embedding API call. **Research Pipeline**: The multi-iteration research pipeline (ResearchJob → ResearchIterationJob → ResearchQueryJob) generates search queries via LLM, then presumably needs to embed them for retrieval. Native retrieval from hidden states could tighten this loop.

**Goal Alignment**: The batch job that scores content against active goals uses vector pre-filtering then LLM scoring. If the LLM scoring step could simultaneously produce embeddings for future retrieval, this would be a meaningful efficiency gain.

**Content Search**: The hybrid search system (70% vector + 30% BM25) relies on pre-computed embeddings. While this paper doesn't directly address document-side embeddings, the query-side optimization is relevant for real-time search.

## [SPD-RAG: Sub-Agent Per Document Retrieval-Augmented Generation](https://arxiv.org/abs/2603.08329v1)

## Paper Summary

SPD-RAG introduces a hierarchical multi-agent framework for multi-document question answering that decomposes retrieval along the **document axis** rather than the task axis. The architecture has three layers: (1) a **Coordination Layer** where a smart coordinator decomposes a user query into atomic extraction tasks and synthesis directives, (2) a **Parallel Retrieval Layer** where each document gets a dedicated sub-agent running an independent RAG loop (retrieve-and-reason) constrained to only its assigned document, and (3) a **Synthesis Layer** that aggregates partial findings through similarity-ordered recursive merging with token-bounded batching.

The key insight is that per-document specialization prevents cross-document distractor chunks from degrading retrieval quality, while enabling cheaper models for document-level extraction (Gemini Flash) with a smarter model only at coordination and synthesis. On the LOONG benchmark, SPD-RAG achieves 58.1 Avg Score vs. 33.0 for Normal RAG and 32.8 for Agentic RAG — a 76% relative improvement — while costing only 38% of the full-context baseline. The gains are most dramatic on tasks requiring exhaustive cross-document synthesis (Clustering: +40.5 points) and on academic papers where standard RAG completely fails (0% perfect rate → 7.5%).

The recursive synthesis mechanism uses agglomerative clustering on embedding similarity to group semantically related findings before merging, ensuring coherent batches within token budgets. While this recursive path wasn't activated in their experiments (findings fit in one pass), it provides a scalability mechanism for larger corpora.

## [How Much Do LLMs Hallucinate in Document Q&A Scenarios? A 172-Billion-Token Study Across Temperatures, Context Lengths, and Hardware Platforms](https://arxiv.org/abs/2603.08274v1)

## Paper Summary

This paper presents a massive empirical study (172 billion tokens, 35 open-weight models) measuring LLM hallucination rates in document Q&A scenarios using the RIKER methodology — a ground-truth-first evaluation approach that generates documents from known facts rather than extracting ground truth from existing documents. This enables deterministic scoring without human annotation or LLM judges.

The key findings are: (1) Even the best model fabricates answers 1.19% of the time at 32K context, with top-tier models at 5-7% and the median model at ~25%; fabrication rates nearly triple at 128K and exceed 10% for all models at 200K. (2) Model selection dominates all other factors — a 72-percentage-point range in accuracy across models, with model family predicting fabrication resistance better than model size. (3) Temperature=0.0 is not universally optimal — it yields best accuracy only 60% of the time, while higher temperatures actually reduce fabrication for 53% of models and dramatically reduce coherence loss (infinite generation loops, up to 48× worse at T=0.0). (4) Grounding ability and fabrication resistance are distinct, weakly correlated capabilities — models excellent at finding facts may still readily fabricate non-existent ones. (5) Hardware platform doesn't meaningfully affect results.

The study's methodological contribution is significant: by generating documents from structured ground truth, RIKER enables contamination-resistant evaluation with deterministic scoring, including explicit "trap questions" about non-existent entities that cleanly measure fabrication tendency.

## [Aligning to Illusions: Choice Blindness in Human and AI Feedback](https://arxiv.org/abs/2603.08412v1)

## Paper Summary

This paper investigates a fundamental vulnerability in Reinforcement Learning from Human Feedback (RLHF): the assumption that human preferences are stable and reliably reportable. Through three experiments, the authors demonstrate what they call the "preference construction problem." First, in a human study (N=50), 91% of surreptitiously swapped preference labels went undetected by annotators, who then confabulated justifications for choices they never made. Second, testing 15 LLM judges as potential replacements for human annotators, the authors found that detection of misattributed preferences relies on shallow text matching rather than genuine self-monitoring — removing prior reasoning from context caused blindness to surge from near-zero to over 50%, and explicit social pressure induced near-universal compliance (median 91.4% sycophancy acceptance). Third, reward models trained under controlled label corruption showed a dangerous dissociation: pairwise accuracy (the standard evaluation metric) remained virtually unchanged even at 30% corruption, while the actual reward signal (margin between chosen/rejected) degraded monotonically, with ED50 at 16-33% corruption depending on architecture.

The most practically significant finding is the "detection gap" — corruption that is invisible to standard metrics but devastating to downstream performance. A Best-of-N evaluation confirmed that at 50% corruption, reward-guided selection produces no improvement over random sampling, yet the proxy model reports monotonically increasing scores. The targeted corruption experiment showed that corrupting ambiguous/close-call pairs (precisely those most susceptible to choice blindness) is far more damaging than uniform random corruption at the same rate. The paper recommends shifting from single-annotation preference labeling toward elicitation methods robust to construction effects: confidence calibration, preference tournaments with consistency checks, and deliberative protocols requiring explicit decision criteria before commitment.

This paper is highly relevant to Decide across multiple product areas, particularly given the **AI Moat** priority and the platform's core mission of improving decision quality.

The finding that 91% of swapped preferences go undetected in third-person evaluative comparison of unfamiliar text is directly analogous to how users evaluate AI-generated options and criteria they didn't author.

**LLM-as-Judge Vulnerability:** Decide uses Claude extensively for structured outputs, trade-off analysis, and AI-generated evaluations. ## [Using Multimodal and Language-Agnostic Sentence Embeddings for Abstractive Summarization](https://arxiv.org/abs/2603.08282v1)

## Paper Summary

SBARThez introduces a modified BART-based architecture that performs abstractive summarization from sentence-level embeddings rather than token-level inputs. The key innovation is replacing the encoder's token embedding layer with a projection layer that accepts pre-computed sentence embeddings from models like LaBSE, SONAR, and BGE-M3. This enables the same architecture to process text in any language and even speech inputs, since the sentence embedding models produce language- and modality-agnostic representations. The paper also introduces a Named Entity Injection (NEI) mechanism that extracts named entities from source documents via NER, tokenizes them, and prepends them to the decoder input — reducing named entity hallucination rates from ~58% to ~34% (matching ground truth levels).

The approach demonstrates three key strengths: (1) significantly more abstractive summaries compared to token-level models (which copy 90%+ of words from source), (2) strong cross-lingual performance especially for low-resource languages where it outperforms translate-then-summarize pipelines and zero-shot LLMs, and (3) effective speech-to-text summarization that bypasses ASR error propagation by operating directly on speech utterance embeddings. The architecture is compact (165M parameters) and achieves competitive ROUGE-L and BertScore while being far more concise and abstract.

## Relevance to Decide

**Meeting Summarization (High Relevance):** Decide already ingests meeting transcripts via Recall AI with WebVTT parsing and generates summaries. The SBARThez approach of operating on sentence/utterance embeddings rather than full transcripts could improve meeting summaries in several ways: (1) bypassing ASR error propagation by using speech embeddings directly from audio segments, (2) producing more abstractive summaries that synthesize key points rather than extracting verbatim phrases, and (3) the NEI mechanism could ensure that person names, company names, and key terms mentioned in meetings are faithfully preserved in summaries.

**Content Search & Goal Alignment (Medium Relevance):** Decide already uses OpenAI `text-embedding-3-small` (1536D) for content indexing and hybrid search. The paper's demonstration that sentence-level embeddings from models like BGE-M3 can serve as effective semantic representations for downstream tasks validates the general approach. However, the specific summarization architecture is more relevant than the embedding choice, since Decide already has a working embedding pipeline.

**Research Pipeline (Medium Relevance):** The multi-iteration research pipeline synthesizes findings into reports. The sentence-embedding-based summarization approach could improve the final synthesis step, particularly when research sources span multiple languages (relevant for international customers or multilingual content).

**Email Summarization & Goal Grouping (Low-Medium Relevance):** The NEI mechanism is directly applicable to email summarization where preserving names, organizations, and specific entities is critical for actionable summaries. The approach of injecting known entities into the decoder could reduce hallucination in any AI-generated content that references specific people or organizations.

**AI Moat Priority (Medium Relevance):** The "premium on token spend" framing is relevant — a compact 165M parameter model that produces competitive summaries from pre-computed embeddings could be significantly cheaper than Claude API calls for routine summarization tasks. This aligns with the goal of making Decide's token spend yield better outcomes than commodity pricing.

## Implementation Approach

### Phase 1: NEI Mechanism for Existing Summaries (Small Experiment, 1-2 weeks)
The most immediately applicable technique is the Named Entity Injection concept, adapted for Decide's existing Claude-based summarization:
- **What to build:** A pre-processing step that extracts named entities from meeting transcripts/emails/documents using spaCy or a similar NER model, then injects them into the prompt template as a structured constraint (e.g., "The following entities appear in the source and should be used accurately: [entity list]")
- **Data needed:** Existing meeting transcripts and their generated summaries for evaluation; manual annotations of hallucinated entities in a sample set
- **Challenge:** English NER is well-supported (unlike the French focus of the paper). The main challenge is measuring improvement — need to build a NEHR-like metric for English content.
- **Modification:** Update `app/prompts/` templates for meeting summaries, email summaries, and research synthesis to include extracted entities.

### Phase 2: Sentence-Embedding Summarization Evaluation (Medium Experiment, 2-4 weeks)
Evaluate whether sentence-level embedding representations improve summarization quality for Decide's use cases:
- **What to build:** An experiment in `experiments/` that takes meeting transcripts, segments them into sentences, computes embeddings using OpenAI's existing embedding model, and evaluates whether feeding these to a smaller fine-tuned model produces competitive summaries vs. Claude
- **Data needed:** Corpus of meeting transcripts with existing Claude-generated summaries as baselines; ideally some human-rated summary quality scores
- **Key challenge:** Decide uses Claude (not a fine-tunable BART model). The sentence-embedding approach would require either (a) fine-tuning an open-source model like BART/T5, or (b) adapting the concept to work with Claude by providing sentence-level semantic summaries as structured input rather than raw transcripts
- **Estimated complexity:** Medium — requires setting up a fine-tuning pipeline for an open-source model, which Decide hasn't done in production yet

### Phase 3: Speech-Direct Meeting Processing (Large Initiative, 4-8 weeks)
If Phase 2 shows promise, explore processing meeting audio directly via speech embeddings:
- **What to build:** Integration with SONAR or similar speech embedding model to generate utterance-level embeddings from meeting audio segments (Decide already has audio via Recall AI)
- **Data needed:** Meeting audio files with corresponding transcripts and summaries for training/evaluation
- **Key challenge:** Audio segmentation (the paper shows 5-second fixed segments work well, which simplifies this), model hosting costs, and latency requirements
- **This bypasses ASR entirely** for the summarization task, potentially reducing error propagation from transcript inaccuracies

### Technical Challenges
1. **Model hosting:** A 165M parameter model is small enough to run on a single GPU, but Decide currently uses API-based LLMs. Would need to evaluate Cloud Run GPU or similar.
2. **Quality gap:** SBARThez achieves competitive but not superior ROUGE/BertScore vs. token-level models. Claude likely produces higher quality summaries. The value proposition is cost reduction and hallucination reduction, not quality improvement.
3. **English adaptation:** The paper focuses on French. Would need to use an English BART model (facebook/bart-large) or multilingual model as the base.

## Expected Impact

**Abstractiveness Improvement:** Current meeting summaries likely over-extract from transcripts (the paper shows token-level models copy 90%+ of words). Sentence-embedding approaches produce genuinely abstractive summaries that are more concise — potentially more useful for busy decision-makers scanning meeting outcomes.

**Activation Impact:** Better, more trustworthy meeting summaries could contribute to the Activation goal by making AI-generated content more reliable and thus more likely to be reviewed weekly.
